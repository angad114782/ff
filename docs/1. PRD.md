# 1. Product Requirements — F&F Stock Checker

## Problem
F&F Global's salesmen need to know, in front of a customer, whether a fabric/furnishing item is in stock, where, and when more is due. That data lives in Microsoft Business Central (BC). Salesmen should not need BC access, and cost/vendor data must stay hidden from them.

## Users
| Role | Needs |
|---|---|
| **Salesman** | Scan a barcode / QR or type an item no, name or SKU; see stock, reserved, available, per-location and per-lot quantities, and PO/delivery status. Works on a phone. |
| **Admin** | Everything a salesman sees plus purchase price and vendor details; manage salesmen, connect BC, see who searched what, manage dashboard content. |

## Goals
1. Live stock answers from BC in a few seconds, on a phone, as an installable PWA.
2. Role-separated data: salesmen never receive cost or vendor information.
3. Admin can run the system without a developer (credentials, users, content, activity).

## In scope (built)
- Login (admin / salesman), password change, admin-set password reset.
- Search by item no / name / SKU, and by barcode/QR scan (camera) — via BC `TradeApp_API_SearchStock`.
- Search list and item detail show **Total Stock = our current stock (sum of lots) + vendor stock**. Item detail also shows who holds how much: our current / reserved / available stock and per-location totals, then vendor total and breakdown.
- Item detail tabs: per-lot table, PO details (qty, status, expected date, transport, bilty), Vendor tab (admin-only vendor details, plus vendor PO).
- Admin: primary API (BC) settings + test, vendors with their own API and response mapping, salesman CRUD + activate/deactivate + reset password, activity logs (logins, searches, reset requests), dashboard stats, hero images and "upcoming products" media (image / PDF / video).
- Salesman dashboard showing admin-uploaded hero carousel and upcoming products.

## Out of scope / not built
- Vendor stock & breakdown per vendor: built (Admin → Vendors); no vendors connected yet.
- FTP stock-file pull, dealer-portal integration, shareable-link generation, domain/hosting settings. API Config holds only the primary API.
- Email delivery (password reset is manual by an admin).
- Offline stock data (the PWA caches the app shell only; stock is always live).

## Open questions
- How BC `QtyPO`, `DeliveryStatus`, `BiltyNo` etc. should be presented vs. the *vendor's* PO (the product owner said PO shown should be the vendor's, from the vendor's API when available).
- Friendly names for BC location codes (`FFDH`, `FFMUM`) — currently shown as-is.
- Vendor APIs: which vendors, auth, and response formats.
- Whether salesmen should see MRP (currently they do; purchase price is admin-only).
