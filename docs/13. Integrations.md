# 13. Integrations

## Microsoft Business Central (primary)
**Endpoint**
```
POST https://api.businesscentral.dynamics.com/v2.0/{tenant_id}/{environment}/ODataV4/TradeApp_API_SearchStock?company=F%26F%20India%20Pvt.%20Limited.
Authorization: Bearer <token>
```
**Token:** `POST https://login.microsoftonline.com/{tenant_id}/oauth2/v2.0/token`, `grant_type=client_credentials`, `scope=https://api.businesscentral.dynamics.com/.default`. Cached in memory until 60 s before expiry; re-fetched on a 401.

**Request body**
```json
{ "collectionCode":"", "brand":"", "category":"", "searchText":"SAN MARINO", "qrCode":"",
  "pageNo":1, "pageSize":20, "sortBy":"", "sortOrder":"" }
```
`searchText` matches item no, item name, SKU. `qrCode` carries a scanned barcode/QR (the item's `qrCode` link, e.g. `https://scan.fandf.in/48fi`).

**Response envelope (double-encoded).** The OData body is `{"@odata.context":…, "value":"<JSON string>"}`; the string parses to `{"value":[ …items ]}`. `unwrap()` handles this.

**Reliability:** 15 s timeout; one retry on network error / 429 / 502 / 503 / 504; auth failures surface as a "check API Config" message to admins and a generic message to salesmen.

### Field map (BC → API)
| BC field | API field | Notes |
|---|---|---|
| `itemNo` | `code` | exact-matched for detail |
| `itemName` | `name` | |
| `collectionCode`, `Color`, `UOM`, `Category`, `ProductLook`, `width`, `*Repeat` | same-named camelCase | |
| `itemFamily` / `ItemFamily` | `family` | BC sends both casings |
| `mrp` | `mrp` | shown to all roles |
| `QtyFree` | `stock.available` | net of sales orders; may be negative |
| `QtySO` | `stock.reserved` | |
| sum of `lots[].quantity` | `stock.current` | equals `QtyFree + QtySO` |
| `lots[]` | `stock.lots`, `stock.locations` | grouped by `locationCode` |
| `QtyPO`, `Transport`, `BiltyNo`, `BiltyDate`, `DeliveryStatus`, `DeliveryDate` | `po.*` | empty strings → `null`; dates are shown as BC sends them |
| `qrCode` | `qrCode` | |
| `PurchasePrices`, `PrimaryVendorName`, `VendorGroup`, `ContactNo`, `ExternalItemId`, `SerachName` | `admin.*` | **admin only** |

**Config:** stored via Admin → API Config (`settings.bc`); env `BC_*` supply defaults.

## Vendor APIs (generic connector)
The primary API gives each item a `PrimaryVendorName` and `ExternalItemId`. Admin → **Vendors** stores one row per vendor: how to call its API (GET/POST, URL with `{{externalItemId}}`, login type) and a **mapping** from that vendor's own response to one normalised result:

```
{ status: 'ok'|'error'|'not_configured', stock, breakdown: [{label, qty}], po: {qty, expected} }
```
- The admin presses **Test** with a sample vendor item number; the server calls the vendor and lists every field found. The form (`client/src/components/FieldMapper.jsx`) shows two columns: the vendor's fields on the left, what we need on the right (*External Item ID, Total stock, Row name, Row quantity, PO quantity, PO expected date*). The admin drags a field up or down until it sits opposite its match, or taps the field and then the row. Each change re-runs the test to refresh the preview. A breakdown given as `{ "Delhi": 10, "Mumbai": 4 }` or a response that is itself a list also works.
- **External Item ID row:** for vendors that return many items. Only rows whose field equals the item's `ExternalItemId` (ignoring case) are kept, and all other fields read from those rows. Vendors that answer for one item put `{{externalItemId}}` in the URL or body instead.
- **Total Stock** = our current stock + vendor stock, in the search list and on item detail. A search with a single match goes straight to detail, so the list makes no vendor call for it.
- Item detail shows vendor total + breakdown under the stock figures (visible to salesmen too, but never the vendor's name). The **Vendor** tab has admin vendor details and vendor PO. No vendor row / switched off → no vendor section, Total is our stock only; vendor down → "Vendor stock could not be loaded", Total is our stock only.
- Safety: https/http only, internal/private addresses blocked, 8 s timeout, 1 MB cap, redirects refused; vendor secrets encrypted at rest and write-only.
- Code: `server/src/services/vendorConnector.js`, `server/src/routes/vendors.js`, table `vendors`.

## Barcode / QR scanning
Client-side `html5-qrcode` (QR, Code 128/39/93, Codabar, EAN-8/13, ITF, UPC-A/E). Decoded text is sent as `barcode=` to `/api/stock/search` → BC `qrCode`. Needs HTTPS or localhost for the camera.

## Not integrated
FTP stock pull, Dealer Portal, other ERPs, domain/hosting settings. API Config holds only the primary API (doc 8).
