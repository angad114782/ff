# 15. Debugging

## Quick checks
```sh
curl localhost:4000/api/health          # server up?
curl localhost:5173/api/auth/me         # Vite proxy → server works? (expect {"user":null})
```
Server logs print to the terminal running `npm run dev:server`; BC problems log as `Business Central error: …`.

## Common problems
| Symptom | Cause / fix |
|---|---|
| `502 Bad Gateway` on `/api/*` in the browser | API server isn't running. Start `npm run dev:server` (both dev processes are needed). |
| `403` on login / any POST in dev | Origin ≠ Host. Vite's proxy must have `changeOrigin: false` (already set in `client/vite.config.js`). If you serve the app from another origin, add it to `CLIENT_ORIGIN`. |
| Server exits: "Invalid configuration" / "Could not connect to MongoDB" | `MONGODB_URI` missing or unreachable (check Atlas IP allowlist and credentials). |
| Can't log in as admin | The admin is created once. Reset it from Profile, or drop the `users` collection to see the setup screen again. |
| "Business Central is not configured" (503) | Fill API Config; all of Tenant ID, Environment, Client ID, Secret are needed. |
| "Business Central rejected the credentials" | Wrong tenant/client/secret, secret expired, or the app registration isn't allowed for BC. Re-enter the secret and Test Connection. |
| BC returns 401/403/404 on search | Wrong environment name or company, or the app isn't registered/permitted in BC. Compare with the working Postman URL: `…/v2.0/{tenant}/{environment}/ODataV4/TradeApp_API_SearchStock?company=…`. |
| Search returns nothing though BC has the item | Check what was sent (`searchText` vs `qrCode`). Scans must be the exact QR link. Check the log row in Admin → Logs. |
| Stored BC secret fails to decrypt (500) | `APP_ENCRYPTION_KEY` changed since it was saved. Re-enter the secret. |
| Everyone signed out after deploy | `JWT_SECRET` changed or isn't persistent. Keep it in env. |
| Camera scan doesn't start | Needs HTTPS or localhost; allow camera permission; another app may hold the camera. |
| Uploads rejected | Type not allowed (hero: jpg/png/webp; upcoming: + pdf/mp4/webm) or > 100 MB. |
| Console shows `chext_*` "unload" violations | A browser extension, not this app. Filter `-chext` or use a clean profile. |
| `path-to-regexp` error on server start | Express 5 doesn't support regex in route params; validate inside middleware. |

## Vendor stock problems
| Symptom | Fix |
|---|---|
| No vendor stock section; Total equals our stock only | No active vendor row whose name matches the item's vendor name exactly (case-insensitive). Check spelling in Admin → Vendors. |
| "Vendor stock could not be loaded" | Vendor API down/slow (8 s limit), login details wrong, or response over 1 MB. Open the vendor and press Test to see the exact reason. |
| Test says "Internal addresses are not allowed" | The URL points at localhost/a private network; vendor APIs must be public. |
| Breakdown empty | Place fields opposite *Row name* and *Row quantity*; the preview refreshes by itself. |
| Preview says no row has the ID | The sample ID is not in the vendor's list, or the wrong field sits opposite *External Item ID*. |
| Search list slow | Each listed item makes one vendor call. A vendor that returns all items every time makes this worse. |

## Inspecting data
```sh
mongosh "$MONGODB_URI" --eval 'db.users.find({}, {email:1,role:1,active:1}).toArray()'
mongosh "$MONGODB_URI" --eval 'db.logs.find().sort({_id:-1}).limit(20).toArray()'
```
(Never print `settings`; it contains the encrypted secret.)

## Debugging BC without the UI
Call the app: sign in (cookie jar) then `curl -b jar "localhost:4000/api/stock/search?q=SAN"`; the server unwraps/maps. To see the raw BC row, temporarily log `rows[0]` in `routes/stock.js` (don't commit; it may contain cost data).
